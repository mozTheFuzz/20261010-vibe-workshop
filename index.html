課前準備 · Windows / Mac

1. 建立 GitHub 帳號

開啟 GitHub 註冊頁

  1. 依頁面提示選擇註冊方式。
  2. 設定帳號資料與使用者名稱。
  3. 完成畫面要求的驗證，確認 Email 已驗證。
  4. 登入後，確認右上角能找到自己的個人帳號。

Windows 與 Mac 都用瀏覽器操作。已有帳號的同學直接登入即可。

完成條件：能登入 GitHub，並記得自己的使用者名稱。

官方指引：https://docs.github.com/en/account-and-profile/how-tos/account-management/creating-an-account-on-github 。頁面可能提供 Email 或其他帳號註冊方式，以實際提示為準。
課前準備 · Windows / Mac

2. 使用 GitHub 帳號註冊 Netlify

開啟 Netlify 註冊頁

  1. 先確認瀏覽器已登入剛才的 GitHub 帳號。
  2. 在 Netlify 註冊頁選擇 GitHub。
  3. 若跳到 GitHub 授權頁，確認帳號後同意登入所需授權。
  4. 回到 Netlify，依畫面完成初始設定。
  5. 能進入 Netlify 管理頁面，就完成帳號準備。

Windows 與 Mac 操作相同。今天先完成註冊，專案部署在課堂進行。

註冊 Netlify 與授權部署某個 GitHub repository 是不同步驟；不要將登入授權誤認為已完成專案串接。參考 https://docs.netlify.com/manage/accounts-and-billing/user-settings/ 。
課前準備 · Windows / Mac

3. 安裝 Antigravity

開啟 Antigravity 官方下載頁，選擇本課使用的 Antigravity IDE。

Windows

在 YouTube 觀看 Windows 教學

選 Windows 與對應架構。
下載後執行安裝程式，依提示完成安裝。
從開始選單開啟 Antigravity。

設定 → 系統 → 關於 → 系統類型：確認 x64 或 ARM64。

Mac

在 YouTube 觀看 Mac 教學

選 macOS 與對應晶片。
打開下載檔，依安裝提示完成。
從「應用程式」開啟 Antigravity。

Apple 選單 → 關於這台 Mac：M 系列選 Apple Silicon，Intel 選 Intel。

官方下載頁同時提供多種產品，講師應指明 IDE，並於課前提供示範使用的版本。遇到系統版本不支援時請先聯絡講師，勿隨意安裝非官方來源。
課前準備 · Windows / Mac

3. 登入並確認 Antigravity 可以使用

  1. 開啟 Antigravity，依初始設定提示操作。
  2. 選擇登入，依提示在瀏覽器完成帳號驗證。
  3. 返回 Antigravity，確認可以開啟專案與使用 AI 對話。
  4. 建立一個「blog-class」資料夾，並在工具內開啟。
第一次交給 AI 的任務請在這個專案建立一個簡單的歡迎網頁，標題是「我的部落格」，並告訴我如何預覽。請先用不需要額外套件的方式完成。

完成條件：看得到網頁，再請 AI 修改標題，確認更新。

官方入門文件：https://antigravity.google/docs 。實際登入方式、介面與可用額度依目前產品及帳號而定。若不能使用 AI，應在課前排除。
課前準備 · Windows / Mac

4. 安裝 Node.js，npm 會一起安裝

Node.js 執行專案工具；npm 用來安裝專案需要的套件。

開啟 Node.js 官方下載頁，選擇 LTS 與自己的作業系統。

Windows

選適合電腦架構的 .msi 安裝檔。
執行安裝，保留 npm 與 PATH 預設選項。
安裝後重新開啟 Antigravity。

Mac

選 macOS 的 .pkg 安裝檔。
打開安裝程式，依提示完成。
安裝後重新開啟 Antigravity。

已有 Node.js 的同學先檢查版本；依講師起始專案要求決定是否更新。

npm 官方安裝文件：https://docs.npmjs.com/downloading-and-installing-node-js-and-npm/ 。簡單 HTML 不一定需要 Node.js，但本課若使用套件與建置工具就需要。講師應固定起始專案支援的 LTS 版本，課堂不另教版本管理器。
課前準備 · Windows / Mac

5. 選擇 Vibe Coding Agent

你可以選擇自己喜歡的 Agent，這堂課我使用 Claude 示範。

開發工具

Antigravity 是我們開啟專案、查看程式與預覽成果的工作環境。

6. 檢查安裝結果

Windows

開啟開始選單，搜尋並開啟「命令提示字元」。

node -v
npm -v

PowerShell 若出現 npm.ps1 執行限制，先用命令提示字元或 npm.cmd -v。

Mac

按 Command + 空白鍵，搜尋並開啟「終端機」。

node -v
npm -v

每行輸入後按 Enter。兩個指令都應顯示版本號。

找不到指令時，先關閉並重開終端機與 Antigravity；仍失敗就把錯誤訊息提供給講師。

另檢查 git --version。若未安裝，依 Git 官方指引完成，Mac 依系統提示安裝開發工具。

Node.js 安裝不等於已安裝 Git，GitHub 帳號也不會自動提供本機 Git。先確認所有同學的 Git 可用。安裝 npm 不需要建立 npm 帳號。

交給 AI 的需求請規劃一個班級部落格，包含文章列表、文章內容與留言區。訪客可以閱讀，登入會員才能留言。請先列出頁面、資料與實作步驟，再開始建立。
先用範例文章，不加文章編輯後台。留言要有規則，會員功能稍後接入。
04 · 部落格功能實作

畫面、規則與資料，各自負責什麼？

前端

顯示文章、留言與輸入框。

後端

處理留言請求，檢查資料與權限。

資料庫

保存文章、會員及留言。

交給 AI 的需求請建立文章與留言畫面，使用共用資料庫儲存留言。每則留言記錄文章、作者、內容與時間。請依起始專案的架構實作，並標明尚未接通的會員功能。

先看到畫面，再確認重新整理與其他瀏覽器能讀到相同資料。

留言只存在本機瀏覽器不等於共用資料庫。未接會員時可先用開發測試資料，正式留言入口需等待會員與權限接通。

05 · 會員功能實作

先定義網站自己的會員

功能規則
註冊建立網站會員資料，同一身分不重複建立
登入確認會員身分，維持登入狀態
留言用登入會員作為作者
刪除只允許作者刪除自己的留言
登出結束登入狀態，不能繼續新增留言

會員資料包含網站會員 ID、顯示名稱與外部身分識別。

先設計網站資料與規則，最後用 LINE 當登入來源。會員註冊可以在第一次 LINE 登入成功時自動完成。
05 · 會員功能實作

先用測試身分，接通會員與留言

交給 AI 的需求請實作會員資料與留言權限。先提供僅限開發環境的測試會員 A、B，用來驗證註冊、登入、登出。後端用登入狀態決定作者，並檢查刪除權限。LINE 串接後替換測試登入，正式環境必須關閉測試入口。

會員 A

新增一則留言。
能刪除自己的留言。

會員 B

看到 A 的留言。
不能刪除 A 的留言。

這裡不另做一套帳號密碼登入。開發測試入口不能成為公開網站的登入漏洞；公開測試前須確認環境隔離或關閉入口。
06 · 測試

我們怎麼知道功能真的完成了？

測試操作預期結果
未登入發表留言後端拒絕，畫面提示登入
會員 A 發表留言留言顯示正確作者
重新整理、換瀏覽器仍能讀到已保存的留言
會員 B 刪除 A 的留言後端拒絕刪除
空白留言、送出失敗顯示清楚提示，不假裝成功
登出後再次留言要求重新登入
除了手動操作，也請 AI 提供對應權限檢查。僅隱藏刪除按鈕不能證明後端權限正確。
06 · 測試

遇到問題，怎麼讓 AI 協助修正？

描述操作與預期

「我用會員 B 刪除 A 的留言，預期應該拒絕。」

描述實際結果

「實際上留言被刪掉了。請檢查後端權限。」

交給 AI 的需求請根據這個重現步驟定位原因，提出修正並說明如何驗證。修正後重新檢查未登入、作者本人及其他會員的操作結果。

修正後，再做同一個測試確認結果。

示範一個錯誤回報。錯誤訊息可以給 AI，秘密金鑰與會員個資需移除。不要只要求「幫我修好」。
07 · 串接 LINE Login

把測試身分換成 LINE 身分

網站入口按下 LINE 登入
LINE 授權使用者登入並同意
後端驗證處理授權回傳
會員登入找到會員或首次建立

LINE 確認外部身分，網站保存自己的會員資料與權限。

首次登入完成會員註冊；再次登入找到同一位會員。

這是概念流程，不是完整協定細節。LINE Login 不等於 LINE 聊天機器人。額外手機或班級資格驗證可以留作課後延伸。
07 · 串接 LINE Login

完成設定，跑一次真正的登入與留言

交給 AI 的需求請將會員登入串接 LINE Login，列出 channel、回呼網址與後端環境變數設定。後端完成身分驗證並維持登入狀態，首次登入建立會員。請處理取消授權，並關閉正式環境的測試登入。

整合驗收

首次登入不漏建會員。
再次登入不重複建立。
登入後能留言，登出後不能。

持續交付

提交並推送新版本。
確認 Netlify 部署結果。
在線上網址再跑一次流程。

課前準備 LINE channel，並確認正式網址的回呼設定。先講測試，再串接，最後仍需整合測試。Git 更新觸發設定好的建置、檢查與部署；自動化測試需要額外配置。
