課程裡遇到的技術名詞

先用一句話抓住概念，再回想它在部落格實作中扮演什麼角色。

Webhook｜事件通知

某件事發生時，服務會主動用 HTTP 通知另一個網址。像是 GitHub 收到新的 push，就通知 Netlify 開始部署。

GitHub：Webhook 說明

API｜程式的溝通介面

API 規定程式可以怎麼提出請求、會收到什麼回應。前端向 /api/posts 要文章，後端就回傳文章資料。

MDN：API 是什麼？

資料庫｜可查詢的長期資料存放處

網站關閉或重新整理後，資料仍能保存，之後也能查找與更新。部落格會把文章、會員和留言存進資料庫。

結構化資料欄位固定、格式一致，例如每則留言都有作者、內容和建立時間。
半結構化資料以欄位名稱描述內容，但每筆資料可以有不同欄位，例如 JSON。
MongoDB：結構化與非結構化資料

CI/CD｜自動檢查與交付

CI 讓程式變更能自動整合、建置和測試；CD 則把通過檢查的版本準備好交付或部署。推送程式碼後自動檢查，是常見的起點。

GitHub Actions：持續整合

Git｜記錄程式變化的版本控制工具

Git 會記錄專案的修改歷史，讓你比較版本、建立分支，也能在需要時回到先前版本。GitHub 則提供遠端儲存與協作功能。

Pro Git：Git 是什麼？

延伸閱讀：網站如何組織？

架構模式是整理程式責任與元件互動的常見方法；它們是思考工具，實際專案可以依需求組合。

軟體架構模式

  • 分層架構：把畫面、應用流程和資料存取分層，讓各層責任較清楚。
  • MVC：Model 管資料與規則、View 呈現畫面、Controller 接收操作並協調兩者。
  • 客戶端－伺服器：客戶端提出請求，伺服器處理後回應；瀏覽器與網站後端就是常見例子。
  • 事件總線：讓元件透過事件傳遞訊息，發送者不必直接認識所有接收者。
  • 清潔／六邊形架構：把核心規則和資料庫、網路等外部工具隔開，方便替換與測試。

Microsoft：架構樣式 · Microsoft：MVC · Microsoft：發布／訂閱模式

髒讀與髒寫｜資料庫交易的並行問題

髒讀是讀到另一筆尚未完成、之後可能被取消的資料；髒寫是覆蓋另一筆尚未完成的修改。交易隔離等機制會限制這類互相干擾。
