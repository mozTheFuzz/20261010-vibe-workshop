01 · 使用者視角 vs 工程師視角

同一個部落格，兩種工作流程

使用者視角

  1. 進入部落格
  2. 用 LINE 登入
  3. 發表留言

工程師視角

  1. 定義部落格功能
  2. 定義會員與註冊功能
  3. 實作與測試留言
  4. 串接 LINE Login

我們用 AI，把使用者的需求一步步變成可以操作的網站。

先展示成品，再切換到工程師視角。開發順序不同於使用者操作順序。這堂課以具備會員與留言功能的部落格為案例。
02 · 所需工具

開始前，準備好三項工具

GitHub 帳號

存放程式碼與版本。

Git 負責版本管理。GitHub 是存放 Git 專案的平台。

Netlify 帳號

部署網站，取得可分享的網址。

連接 GitHub，程式更新後觸發部署。

Antigravity

用自然語言請 AI 建立與修改程式。

課前完成安裝與登入。Agent 可自由選擇，本課以 Claude 示範。

課前小任務請用 Antigravity 產生一個簡單網頁，並成功預覽。確認工具能使用，再開始課堂實作。
課堂先帶四個操作：開啟專案資料夾、描述需求、預覽成果、提出具體修改。完整留言與登入也需要資料庫及 LINE Login channel；講師應課前準備好設定與可部署的起始專案，或給同步實作同學設定指引。Git 本身沒有帳號。
03 · 我們來實作吧！

一個讓會員註冊、留言的部落格

所有人可以閱讀文章，會員登入後可以發表留言。

部落格定義文章、閱讀、留言
會員定義註冊、登入、權限
測試確認資料與功能
LINE Login接入真實身分
今天的完成條件文章能閱讀、留言能保存、留言能辨識作者，最後使用 LINE 登入完成留言。
建議節奏：視角與工具 8 分鐘、需求分解 5 分鐘、部落格 15 分鐘、會員 12 分鐘、測試 8 分鐘、LINE 串接 12 分鐘。部署穿插在實作中。這是使用準備好起始專案的示範安排。
04 · 部落格功能實作

先定義網站需要做什麼

文章功能

文章列表
文章內容頁
標題、摘要與內容

留言功能

閱讀留言
新增留言
刪除自己的留言

交給 AI 的需求請規劃一個班級部落格，包含文章列表、文章內容與留言區。訪客可以閱讀，登入會員才能留言。請先列出頁面、資料與實作步驟，再開始建立。
先用範例文章，不加文章編輯後台。留言要有規則，會員功能稍後接入。
04 · 部落格功能實作

畫面、規則與資料，各自負責什麼？

前端

顯示文章、留言與輸入框。

後端

處理留言請求，檢查資料與權限。

資料庫

保存文章、會員及留言。

交給 AI 的需求請建立文章與留言畫面，使用共用資料庫儲存留言。每則留言記錄文章、作者、內容與時間。請依起始專案的架構實作，並標明尚未接通的會員功能。

先看到畫面，再確認重新整理與其他瀏覽器能讀到相同資料。

留言只存在本機瀏覽器不等於共用資料庫。未接會員時可先用開發測試資料，正式留言入口需等待會員與權限接通。
04 · 部落格功能實作

第一版完成，就先部署一次

Git + GitHub

保存一次修改版本。
把程式碼推送到遠端專案。

Netlify

連接 GitHub 專案。
依架構設定建置與環境變數。

取得網站網址，從手機或另一個瀏覽器開啟。

交給 AI 的需求請依現有專案整理 Netlify 部署步驟，列出前端、後端與資料庫需要的設定。秘密值放在後端環境變數，並告訴我如何確認部署成功。
部署貫穿實作，不再另外增加一大段理論。純靜態 HTML 不足以獨自完成安全登入與多人共用留言，需要相容的後端函式或外部後端服務與資料庫。
05 · 會員功能實作

先定義網站自己的會員

功能規則
註冊建立網站會員資料，同一身分不重複建立
登入確認會員身分，維持登入狀態
留言用登入會員作為作者
刪除只允許作者刪除自己的留言
登出結束登入狀態，不能繼續新增留言

會員資料包含網站會員 ID、顯示名稱與外部身分識別。

先設計網站資料與規則，最後用 LINE 當登入來源。會員註冊可以在第一次 LINE 登入成功時自動完成。
05 · 會員功能實作

先用測試身分，接通會員與留言

交給 AI 的需求請實作會員資料與留言權限。先提供僅限開發環境的測試會員 A、B，用來驗證註冊、登入、登出。後端用登入狀態決定作者，並檢查刪除權限。LINE 串接後替換測試登入，正式環境必須關閉測試入口。

會員 A

新增一則留言。
能刪除自己的留言。

會員 B

看到 A 的留言。
不能刪除 A 的留言。

這裡不另做一套帳號密碼登入。開發測試入口不能成為公開網站的登入漏洞；公開測試前須確認環境隔離或關閉入口。
06 · 測試

我們怎麼知道功能真的完成了？

測試操作預期結果
未登入發表留言後端拒絕，畫面提示登入
會員 A 發表留言留言顯示正確作者
重新整理、換瀏覽器仍能讀到已保存的留言
會員 B 刪除 A 的留言後端拒絕刪除
空白留言、送出失敗顯示清楚提示，不假裝成功
登出後再次留言要求重新登入
除了手動操作，也請 AI 提供對應權限檢查。僅隱藏刪除按鈕不能證明後端權限正確。
06 · 測試

遇到問題，怎麼讓 AI 協助修正？

描述操作與預期

「我用會員 B 刪除 A 的留言，預期應該拒絕。」

描述實際結果

「實際上留言被刪掉了。請檢查後端權限。」

交給 AI 的需求請根據這個重現步驟定位原因，提出修正並說明如何驗證。修正後重新檢查未登入、作者本人及其他會員的操作結果。

修正後，再做同一個測試確認結果。

示範一個錯誤回報。錯誤訊息可以給 AI，秘密金鑰與會員個資需移除。不要只要求「幫我修好」。
07 · 串接 LINE Login

把測試身分換成 LINE 身分

網站入口按下 LINE 登入
LINE 授權使用者登入並同意
後端驗證處理授權回傳
會員登入找到會員或首次建立

LINE 確認外部身分，網站保存自己的會員資料與權限。

首次登入完成會員註冊；再次登入找到同一位會員。

這是概念流程，不是完整協定細節。LINE Login 不等於 LINE 聊天機器人。額外手機或班級資格驗證可以留作課後延伸。
07 · 串接 LINE Login

完成設定，跑一次真正的登入與留言

交給 AI 的需求請將會員登入串接 LINE Login，列出 channel、回呼網址與後端環境變數設定。後端完成身分驗證並維持登入狀態，首次登入建立會員。請處理取消授權，並關閉正式環境的測試登入。

整合驗收

首次登入不漏建會員。
再次登入不重複建立。
登入後能留言，登出後不能。

持續交付

提交並推送新版本。
確認 Netlify 部署結果。
在線上網址再跑一次流程。

課前準備 LINE channel，並確認正式網址的回呼設定。先講測試，再串接，最後仍需整合測試。Git 更新觸發設定好的建置、檢查與部署；自動化測試需要額外配置。
